# OpenATF Domain Model (Ubiquitous Language)

**Document Version:** 1.0

**Project Name:** OpenATF (Open Agent Test Framework)

---

# 1. Purpose

This document defines the business language of OpenATF.

Every developer, AI Agent, plugin, workflow and service must use the same terminology.

A single concept must have only one meaning throughout the framework.

---

# 2. Domain Overview

OpenATF is an AI-native Quality Engineering Platform.

The platform consists of Projects.

Projects contain Plugins.

Plugins expose Business Domains.

Business Domains expose Capabilities.

Capabilities contain Business Processes.

Business Processes execute Workflows.

Workflows create Tasks.

Tasks are executed by Services.

Services communicate through Adapters.

# 4. Domain Definitions

## Project

Represents one automation implementation.

Examples

- Salesforce CRM
- SAP ECC
- Oracle Fusion
- Banking Portal

A Project may contain multiple plugins.

---

## Plugin

Represents an application extension for OpenATF.

A plugin contains all business knowledge for one application.

Example

Salesforce Plugin

SAP Plugin

ServiceNow Plugin

---

## Business Domain

Represents a major functional area.

Examples

Sales

Service

Marketing

Finance

Procurement

---

## Capability

Represents a business feature.

Examples

Accounts

Contacts

Leads

Invoices

Purchase Orders

Users

Capabilities describe **what the system can do**.

---

## Business Process

Represents how organizations use a capability.

Examples

Create Customer

Approve Invoice

Convert Lead

Generate Quote

Business Processes may differ by country.

---

## Workflow

Represents an executable business flow.

Examples

Germany Account Creation

India GST Validation

Japan Customer Approval

A Workflow is composed of Tasks.

---

## Task

Smallest executable unit.

Examples

Launch Browser

Login

Create Account

Validate Toast Message

Capture Screenshot

Generate Report

A Task has

- Status
- Priority
- Retry Policy
- Timeout
- Dependencies

---

## Agent

An AI reasoning component.

Agents make decisions.

Agents never execute automation.

Examples

Requirement Agent

Planning Agent

Validation Agent

RCA Agent

---

## Service

Performs business operations.

Examples

Execution Service

Reporting Service

Knowledge Service

Configuration Service

---

## Adapter

Communicates with external technologies.

Examples

Playwright

Ollama

Jira

Slack

GitHub

---

## Execution Context

Represents the shared state of one execution.

Contains

Project

Plugin

Country

Browser

Workflow

Environment

Current Task

Execution ID

Variables

Reports

Logs

Screenshots

Videos

Metrics

Every component reads and updates the Execution Context.

---

## Command

Represents a user request.

Examples

Run Smoke Suite

Execute Germany Regression

Generate Report

Analyze Requirement

Commands start workflows.

---

## Event

Represents something that happened.

Examples

WorkflowStarted

TaskCompleted

TaskFailed

ExecutionFinished

Events are immutable.

---

## Execution Plan

Represents the strategy generated by the Planning Agent.

Contains

Tasks

Dependencies

Execution Order

Estimated Duration

Priority

---

## Execution Result

Represents the final outcome.

Contains

Status

Duration

Reports

Artifacts

Defects

Metrics

---

## Report

Represents execution outputs.

Examples

HTML Report

Allure Report

Daily Status Report

Release Report

---

## Environment

Represents where execution occurs.

Examples

DEV

SIT

UAT

PREPROD

PRODUCTION

---

## Requirement

Represents business requirements.

Can originate from

Jira

Confluence

User Story

Release Notes

Document

---

## Test Case

Represents a single validation.

A Test Case belongs to a Workflow.

---

## Test Suite

Represents a collection of related Test Cases.

Examples

Smoke

Regression

Sanity

API

Security

Accessibility

# 6. Naming Rules

Every domain object must have

- One responsibility
- One definition
- One owner

No duplicate concepts are allowed.
